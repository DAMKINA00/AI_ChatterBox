# 0.4.8 채팅별 일시 정지·재시작 및 승인 접수 검증

검증일: 2026-10-15. 기준 커밋: 0.4.7 `87edf19`.

## 동작

- 우측 상단 중지 버튼을 제거하고 마스터 채팅 입력창의 빈 공간에 아이콘 버튼을 둡니다. 작업·승인 대기 중에는 일시 정지, 중지 확인 중에는 비활성 진행 표시, 정지 상태에서는 재생 아이콘입니다. 대기·완료·오류에는 숨기고 작업자 기록에는 표시하지 않습니다. 왼쪽 채팅 행에도 일시 정지 상태 아이콘이 표시됩니다.
- 일시 정지는 해당 채팅의 마스터·작업자 드라이버에 실제 중지 요청을 보내고 승인 판단도 취소합니다. 네이티브 실행 종료와 이미 수락한 협의 큐의 정리를 기다린 뒤 `paused`로 바꿉니다. 확인 전에는 재시작하지 않습니다. 다른 채팅의 드라이버에는 중지를 보내지 않습니다.
- 지시 ID·배정/리뷰 횟수·작업자/CLI 세션·미완료 요청·파일 범위·부분 응답·추가 지시를 보관합니다. 재생 시 같은 담당자에게 미완료 요청을 재전달하고 마스터에게 취합을 이어가도록 요청합니다. 계속하는 요청은 새 배정 횟수로 중복 계산하지 않습니다. 이미 끝난 작업은 재실행하지 않도록 안내합니다.
- 승인 대기는 만료시키므로 재시작 후 필요한 권한은 새로 요청합니다. 정지 중에는 브리지 작업과 도구 승인을 막고, 계획·리뷰의 수정 금지와 범위를 유지합니다. 추가 메시지는 정지 상태를 유지한 채 보관합니다.
- 정지 정보는 앱 데이터에 저장됩니다. 앱 재실행 시 `paused`는 유지하고 중지 도중 종료된 `pausing`은 `paused`로 복구합니다. 작업 폴더가 바뀌면 원래 폴더로 복원하기 전까지 재시작을 거부합니다. 기존 `/stop` 명령은 계속하기 정보를 지우는 중지로 유지합니다.
- 승인·거부 클릭 즉시 전달 중 표시로 접수를 알리고 중복 버튼을 비활성화합니다. IPC가 실제 처리한 결정을 돌려주면 UI에서 즉시 결과를 표시합니다. 만료·실패는 각각 표시하거나 재시도 가능 상태로 돌립니다. 승인 처리 경로는 다른 마스터의 생성·응답·판단 완료를 기다리지 않습니다. 승인 판단 초기화 취소도 채팅별로 분리했습니다.

## 검증 범위

앱의 실행 제어는 가짜 드라이버로, 화면은 지연시킨 IPC 응답과 합성 이벤트로 확인했습니다. 실제 사용자 CLI/웹 모델을 중지·재개하거나 고위험 명령을 승인하지 않았습니다. 네이티브 중지 요청은 이미 실행한 파일 변경을 되돌리는 기능이 아니며, 모델이 중지 확인을 늦게 보내면 중지 확인 상태가 유지됩니다. 실제 환경의 모델·프로세스 부하에 따른 지연은 이번 격리 검증만으로 완전히 제거됐다고 판단하지 않습니다. 실행 중인 프로덕션 앱은 종료하지 않았고 새 포터블 적용은 기존 작업 종료 후 진행해야 합니다.
