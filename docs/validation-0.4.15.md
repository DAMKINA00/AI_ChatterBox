# 0.4.15 헤더와 CLI 사용량 조회 검증

검증일: 2026-10-19. 기준 커밋: `fe68f4c`.

## 수정

- 헤더를 제목, 마스터·승인 방식, 클로드·지피티·제미나이·그록의 세 행으로 나눴습니다. 제목의 말줄임을 제거하고 긴 제목은 줄바꿈합니다. 프로젝트 경로는 제목 행의 오른쪽에 표시하며, 모델 설정 줄은 좁은 창에서 가로로 스크롤합니다.
- Grok은 사용량 화면 항목만 있고 수집 경로가 없었습니다. 로그인한 CLI의 ACP `initialize` → `authenticate` → `_x.ai/billing`을 연결했습니다. 세션 생성이나 모델 프롬프트를 보내지 않습니다. 주간·월간 한도와 초기화 시각을 구분합니다.
- Grok의 정상 기간 응답에서 사용률이 생략된 경우는 공식 CLI의 `credit_balance_from_config`와 같은 0% 규칙을 따릅니다. 빈 응답이나 잘못된 기간·숫자는 사용량으로 만들지 않습니다. 참고: [공식 billing 형식](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-shell/src/extensions/billing.rs), [공식 표시 변환](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-pager/src/app/effects/helpers.rs).
- Gemini는 프로덕션 설정에 일반 오류가 저장돼 있었으나 직접 명령과 기존 수집 함수의 현장 재조회는 정상 응답했습니다. 과거 오류의 단일 원인은 확정하지 못했습니다. 성공 `/usage` JSON이 출력됐는데 프로세스 종료가 지연되어 오류가 함께 반환되는 경우까지 실패로 버리던 경로를 수정했습니다. 입력 파이프를 닫고 조회 제한을 45초로 조정했으며 로그인 필요·시간 초과·응답 형식 오류를 구분합니다. 대화 ID나 실제 턴·토큰 소비가 있는 응답은 사용량 명령 결과로 인정하지 않습니다.
- 제공자별 조회를 분리해 Codex 준비가 동기적으로 실패해도 Gemini/Grok을 조회합니다. 왼쪽의 새로고침은 실제 조회 완료까지 대기 표시를 유지하고 새 스냅샷을 반영합니다. 최초 화면 로딩과 정기 조회는 계속 비동기로 동작합니다.
- 화면 초기화가 CLI 인증을 기다리는 동안 새 사용량이 도착하면 수신기를 등록하기 전이라 응답을 놓치고 이전 오류 스냅샷을 표시하는 순서 문제를 재현했습니다. 사용량 수신기를 초기화 첫 단계에 등록하고, 시작 중 받은 최신 응답을 초기 스냅샷보다 우선하도록 고쳤습니다. 동일 UI 회귀가 수정 전 실패하고 수정 후 통과하는 것을 확인했습니다.

## 현장 확인

Antigravity 1.4.2에서 `/usage`의 `SUCCESS`, 0턴, 주간·5시간 버킷을 확인했습니다. Grok 1.0.62에서 `_x.ai/billing`의 주간 기간 응답을 읽고 실제 수집 함수가 주간 사용량을 반환하는 것을 확인했습니다. 조회를 위해 사용자 비밀번호·토큰을 읽어내거나 모델 프롬프트를 보내지 않았습니다.

## 검증 범위

화면 검증은 임시 DB와 가짜 IPC 응답을 사용합니다. 실제 계정의 읽기 전용 조회와 합성 회귀 검증은 구분합니다. 실행 중인 프로덕션 앱은 종료하거나 재시작하지 않으므로 새 포터블로 실행해야 수정이 적용됩니다.
