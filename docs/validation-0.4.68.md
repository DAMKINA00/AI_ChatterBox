# v0.4.68 — 계획 자동 삭제와 계획 모드 진행 확인

2026-11-25, Windows x64.

## 변경

- 새 계획이 시작되면 계획 카드의 '이전 계획' 목록을 더 이상 쌓지 않고 비웁니다. 카드에는 현재 계획만 남습니다. (DB의 과거 계획 이벤트를 물리적으로 지우는 일괄 정리는 하지 않습니다.)
- 계획 모드에서 마스터가 계획을 제출하면 토글이 자동으로 꺼지고, 앱이 [진행 / 수정 / 취소] 확인 카드를 띄웁니다. 질문이 빠지지 않도록 마스터 대신 앱이 묻습니다.
  - 진행: 승인 버튼과 같은 `plan-run planId:version` 경로로 실행합니다. 마스터 턴이 도는 중에 골랐다면 턴이 끝나 승인 대기가 기록되는 즉시 실행합니다.
  - 수정: 승인 대기를 유지하고 다음 메시지를 수정 요청으로 받아 새 버전 계획(읽기 전용 계획 턴)으로 처리합니다. 토글이 꺼져 있어도 미승인 제안이 있으면 수정 턴이 됩니다.
  - 취소: 기존 `plan-cancel` 경로를 탑니다.
  - 승인 버튼·취소·새 메시지는 열려 있던 카드를 닫고, 그 뒤 늦게 답해도 아무것도 실행하지 않습니다.
- 데스크톱(PlanPanel)과 원격 웹의 체크리스트/계획 패널을 펼쳤을 때 항목이 많으면 세로로 스크롤됩니다.
- 경쟁 조건 보완:
  - 진행 결정을 제출 이벤트 ID·epoch에 묶고 실행·취소 직전에 현재 제출·지시·중지 상태를 다시 검증합니다. '진행' 선택 후 턴 종료 직후 `/stop`이 와도 유령 실행되지 않습니다.
  - 제출 직후/턴 중 보낸 수정 메시지가 현재 턴의 도구 응답으로 소비되지 않도록 별도 보관소에 두고 턴 종료 후 수정 턴에서만 소비합니다.
  - 계획 턴이 오류로 끝나면 보관된 수정 요청을 자동 전달하지 않으며, 정상 전달도 읽기 전용 계획 턴으로만 제한해 쓰기 가능한 일반 턴을 시작하지 않습니다.

## 검증

- TypeScript main/renderer 통과(node·web).
- 단위 테스트 834개 모두 통과(`node scripts/test-unit.mjs`): 이전 계획 삭제, 제출 시 토글 꺼짐, 진행/수정/취소, 재제출 경쟁, 중지 직후 유령 실행 방지, 수정 요청 보관, 오류 종료 처리, 원격 idle 카드 응답, 스크롤 클래스 포함.
- e2e 계획 생명주기 스크립트(`scripts/e2e-plan-lifecycle-20261110.mjs`)는 새 동작(이전 계획 없음)에 맞게 갱신하고 `node --check`로 문법만 확인했습니다.
- 비작성자 교차 리뷰(지피티)를 네 차례 거쳐 지적을 반영했고, 최종 리뷰는 pass입니다.

실제 앱 화면과 실제 CLI 세션에서의 수동 확인, e2e 실제 실행은 하지 않았습니다. 기존 DB에 이미 쌓인 과거 계획 기록은 다음에 새 계획이 시작될 때부터 비워지며, 기존 누적분 일괄 정리는 하지 않았습니다.
