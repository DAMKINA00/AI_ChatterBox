# 0.4.58 — 작업자 취합과 작업별 계획

## 변경

- 일반 `ask`의 마스터 응답은 협의 ID·상태·파일 수·리뷰 판정만 반환한다. 실패 시 짧은 원인을 포함하며 작업자 보고서 본문과 계정 진단은 기본 전달하지 않는다.
- 마스터의 복수 `ask_parallel`은 각 배정을 마친 뒤 `coordinator`(생략 시 성공한 첫 담당자)가 원문을 조회하고 필요한 동료 확인을 거쳐 취합한다. 마스터는 통합 결론과 배정 성공·실패 수만 받는다. 단일 배정과 작업자끼리의 병렬 질문에는 취합 턴을 추가하지 않는다.
- 순차 작업의 마지막 취합은 마스터가 담당자에게 협의 ID들을 주고 `ask(summary=true)`로 요청한다. 최종 결론 본문은 최대 400자를 전달하며 상태·리뷰 경고·주요 산출물 3개는 별도로 붙인다. 긴 응답의 발췌는 표시하고 원문은 삭제하지 않는다.
- `read_consult`로 같은 채팅의 결과만 조회한다. 작업자의 기본 조회는 제한된 발췌, 마스터의 기본 조회는 짧은 결론이며 `detail=true`는 전체 보고서·파일 목록·구조화 리뷰를 페이지별로 제공한다. 원문 조회에는 외부 모델 호출이 없다.
- 그룹의 자동 결과 알림, 팀 목록, 상태 점검에 원문 보고서를 반복 첨부하지 않는다. 이미 도구 응답으로 받은 결과의 알림 사본도 제외한다. 직접 동료 메시지와 실제 사용자 지시는 보존한다.
- 추가 지시는 활성 실행에서 한 번 전달하고 일시 정지 후 재개 시 다시 제공한다. 원문 조회 등 JSON 결과와 추가 지시는 별도 내용 블록으로 전달한다. 분리된 병렬 작업의 취합까지 기다린 후 마스터를 재개하며 중지 후 새 취합을 시작하지 않는다.
- 새 작업은 이전 계획을 완료/미완료 상태로 기록하고 빈 계획 경계를 만든 뒤 현재 작업의 계획을 작성하게 한다. 진행 중 추가 지시와 승인된 `/plan` 실행은 같은 계획을 유지한다. 이전 단계·취소 이유·리뷰 기록과 실제 산출물은 유지한다.
- Antigravity에서도 결과 조회·작업자 상태·구조화 리뷰 도구를 사용할 수 있도록 앱 도구 목록을 맞춘다.

## 검증 범위

회귀 테스트는 가짜 드라이버와 임시 DB를 사용한다. 결과 원문 복원, 채팅 간 조회 차단, 실패 및 미제출 리뷰 보존, 담당자 간 직접 확인, 취합 중 즉시 질문·중지·재개, 새 작업 계획 분리, 기존 `/plan` 승인·취소와 계정 격리를 확인한다.

실제 모델 요청과 설치·실행 중 앱의 재시작은 하지 않는다. 기존 모델 세션에 이미 누적된 컨텍스트는 삭제하지 않는다. 취합용 작업자 턴이 추가되므로 전체 모델 비용의 절감률은 별도 실측이 필요하다.

Node/Web 타입 검사와 전체 테스트 736/736을 통과했다. 최종 프롬프트 문구를 맞춘 뒤 관련 회귀 128/128과 Electron Vite 소스 빌드를 다시 통과했으며 모두 정상 종료를 확인했다.

중간 전체 실행에서는 기존 긴 채팅 페이지 성능 테스트가 첫 페이지 1,724ms로 시간 기준을 넘었다. 해당 테스트의 별도 실행과 최종 전체 실행은 통과했으며 시간 기준을 완화하거나 조회 코드를 변경하지 않았다. 실제 운영 환경의 응답 시간은 이번 결과만으로 보장하지 않는다.
