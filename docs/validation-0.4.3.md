# 0.4.3 검증 기록

검증일: 2026-10-15. 원격 `main`의 0.4.2 커밋 `8136640`을 기준으로 로그인 완료 피드백과 주제별 직접 토의를 추가했습니다. 여러 웹 계정 배정·대기·인계와 기존 데이터 형식을 유지합니다.

## 변경 내용

- 웹 계정별 명시적 로그인 확인을 추가했습니다. Gemini 입력창·모델 표시와 로그인 버튼 상태로 완료를 확인하고 해당 계정 번호로 완료 안내를 보냅니다. 초안이나 생성 중인 응답이 없으면 창을 숨깁니다. 로그인 세션과 숨긴 창은 재사용합니다.
- 수동 브라우저 열기, 작성 중인 내용, 작업자 소유 창은 유지합니다. 수동 닫기·종료·작업자 배정 시 로그인 확인을 취소합니다. OAuth/보안 확인 페이지를 완료로 오인하지 않으며 추가 보안 확인은 사용자가 직접 수행합니다.
- 마스터 `ask`와 `ask_parallel` 항목에 선택적인 `discussion: {topic, peers}`를 추가했습니다. 클로드·지피티 진행자가 지정된 작업자에게 직접 `ask`로 질문하고 그룹 결과를 마스터에게 반환합니다. 기존 협의 기록에 주제·요청·응답·배정 이유·추론 수준을 저장합니다.
- 기술 토의는 `opinion`, 문장·대사 토의는 `writing`으로 실행하며 파일을 고치지 않습니다. Gemini는 글쓰기 그룹에만 참여합니다. 중요한 오류의 독립 조사와 구현 범위·승인·교차 리뷰·순환 대기 차단을 유지합니다. 참여자 응답이 없으면 그룹 협의를 오류로 기록합니다.

## 실제 CLI 토의 검사

`scripts/smoke-peer-discussion.mjs`를 격리된 데이터 폴더에서 실행했습니다. 실제 Claude 마스터와 Claude 진행자, Codex `gpt-6.1-sol` 참여자가 로그인 완료 문구라는 가상의 주제로 의견을 주고받았습니다. 제품 소스·사용자 문서·프로덕션 대화는 입력하지 않았고 파일 변경·명령·웹 호출은 허용하지 않았습니다.

확인한 흐름: 마스터가 두 작업자 생성 → 그룹 배정 → 클로드 진행자가 지피티에게 직접 질문 → 지피티 실제 응답 → 진행자가 수정안을 취합 → 마스터 최종 응답 → 작업자 해제·CLI 기록 보관.

실제 저장된 기록의 **9/9** 검증을 확인했습니다. 최초 검사에서 마지막 응답의 시간순 조건이 실패했으나, 검증 스크립트가 이벤트의 `at` 대신 존재하지 않는 `ts`를 사용한 것이 원인이었습니다. 스크립트를 수정하고 같은 실행의 SQLite 기록을 다시 확인했습니다. 최초 `results.json`을 보존하고 정정 근거·참여자 완료 시각·마스터 취합 시각을 `results-reviewed.json`에 남겼습니다. 실제 호출을 다시 수행한 결과로 표현하지 않습니다.

근거: `.scratch/peer-discussion-live-1792023052876/`의 격리 DB·이벤트 기록·`results.json`·`results-reviewed.json`. 자동 허용한 권한은 이 테스트 안의 낮은 위험 앱 브리지 `set_expression`·`ask`·`agents`뿐이며 제품 승인 정책을 변경하지 않았습니다.

## 검증 범위와 미확인 항목

- 새로운 실제 Google 로그인·추가 보안 확인을 사용자 계정으로 재수행하지 않았습니다. 로그인 창 검사는 로컬 fixture와 실제 Electron 창 검증입니다. 실제 Google 웹 구조가 바뀌면 연결 확인에 실패할 수 있습니다.
- 실제 CLI 토의 검사는 Claude 마스터와 두 명의 Claude/Codex 작업자에 대한 텍스트 토의 한 건입니다. GPT 마스터, Gemini 웹 참여, 많은 동시 그룹의 실제 모델 호출은 이번에 별도로 수행하지 않았습니다. 해당 분기와 제한은 자동 테스트로 확인했습니다.
- 기존 프로덕션 앱과 진행 중인 작업은 중단하지 않았습니다. 새 포터블을 만들었다는 사실과 실행 중인 앱이 새 버전이라는 사실은 구분합니다. 작업 종료 후 새 실행 파일을 실행해야 변경이 적용됩니다.
