# 0.4.39 검증 기록

## 원인과 수정

Grok CLI 1.0.70이 보내는 승인 콜백은 `_x.ai/hooks/run`인데, 앱은 `x.ai/hooks/run`만 처리했습니다. 콜백 처리가 누락되어 앱 승인 목록에 도구가 등록되지 않았고, 뒤따르는 `session/request_permission`이 거절되면서 `cancelled`로 종료됐습니다.

사용자가 보고한 실패 기록에는 `permission_rejected`와 도구 거절이 남아 있었습니다. 별도의 임시 폴더에서도 수정 전 동일한 현상을 재현했습니다. 현재·기존 콜백 이름을 같은 승인 처리기로 연결하며, 세션·콜백·도구 ID, 잘린 입력 차단과 승인 정책은 바꾸지 않습니다.

원격 웹 기능이 포함된 v0.4.38 (`3240a39`)을 먼저 반영하고 이 수정은 v0.4.39로 구분했습니다.

## 자동·실제 CLI 검증 (2026-11-05)

- 수정 전 현재 콜백 회귀 검사가 `지원하지 않는 Grok 요청: _x.ai/hooks/run`으로 실패하고, 기존 콜백 검사는 통과했습니다.
- v0.4.38 통합 후 전체 단위 검사 520/520, Node/Web TypeScript 타입 검사 통과.
- 현재·기존 콜백 모두 승인 완료 후에만 `allow_once`를 선택하는 것을 검사했습니다. 미승인·거부·다른 세션·잘린 입력·알 수 없는 콜백은 허용하지 않습니다.
- 실제 Grok CLI의 격리 작업에서 임시 `probe.txt`만 작성하도록 앱 승인기를 제한했습니다. 승인 콜백 → 앱 허용 → ACP `allow-once` → 파일 내용 일치 → `turn_end.ok=true`를 확인했습니다. 수정 전에는 같은 작업이 `cancelled`로 끝났고 파일이 생성되지 않았습니다.
- 원격 웹 화면을 포함한 빌드 출력 174개가 설치 패키지와 일치합니다. Windows x64 NSIS 설치 후 v0.4.39.0과 설치된 app.asar 일치를 확인했습니다. 기존 DB는 백업했으며 설치 전후 SHA-256이 동일합니다.

## 검증 한계

실제 CLI 검증은 임시 텍스트 파일 작성으로 진행했습니다. 사용자가 실패한 이미지 생성·편집 작업 자체는 대신 실행하지 않았습니다.
