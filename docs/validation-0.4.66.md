# v0.4.66 — 사용량 모니터 캐릭터 개별 선택

2026-11-24, Windows x64.

## 변경

- 트레이의 `사용량 모니터 설정 > 캐릭터 표시`가 캐릭터별 하위 메뉴가 됩니다. 마스터(Orch)·클로드·지피티·제미나이·그록 체크박스와 `모두 표시`·`모두 숨기기`가 있습니다. 모니터가 상태에 `characterSet`을 보내면 이 메뉴를, 보내지 않는 이전 모니터에는 기존 단일 스위치를 보여 줍니다.
- 새 호스트 명령 `{"command":"character","value":{"id":"gpt","on":true}}`로 한 캐릭터만 켜고 끕니다. `모두 표시`는 앞선 명령의 응답을 기다리지 않아도 다섯 명이 모두 켜지도록 다섯 ID 모두에 켜기 명령을 보내고, `모두 숨기기`는 기존 `characters=false`를 사용합니다.
- 모니터가 다시 시작되면 이전 프로세스의 상태를 지워 첫 상태를 받기 전까지 모니터 메뉴를 비활성화하고, 실제로 보내기 직전에 받을 프로세스가 개별 선택을 지원하는지 다시 확인합니다. 종료된 프로세스의 늦은 출력은 새 프로세스의 상태를 덮어쓰지 않습니다.
- 다섯 캐릭터의 표정 원화 60장(1254×1254 RGBA)을 교체했습니다.
- 함께 설치되는 AI 사용량 모니터: `02728a02d3bd39ef87b1649f74ba4b0eee3c8ff6` (부모 `b34a238` → `fb9488b`).

## 검증

- TypeScript main/renderer 통과.
- 단위 테스트 786개 중 785개 통과. 실패 1개는 이 변경과 무관한 긴 채팅 페이지 성능 시간 제한(`first page took …ms`)이며 해당 파일 단독 실행은 19/19 통과합니다. 트레이 메뉴(개별·전체·이전 모니터), 상태 정규화, 명령 검증, 이전 모니터 재연결, 지연 응답 순서, 종료된 프로세스의 늦은 EOF 회귀 테스트를 포함합니다.
- 설치파일에 포함된 실제 `AIUsageMonitor.exe`를 별도 데이터 폴더(`AIUSAGEMONITOR_DATA_DIR`)로 실행하고, 트레이 메뉴 정의의 클릭 처리 → 호스트 연결 코드 경로로 13개 통합 검사 통과: 단일·복수 선택, 개별 해제, 모두 표시·모두 숨기기, 세 번의 재시작 후 선택 복원.
- PNG 60장 디코딩·크기·투명 채널과 코드의 경로 매핑 확인.

실제 트레이 아이콘의 우클릭 메뉴는 앱이 격리 테스트 모드에서 모니터 연동을 끄기 때문에 직접 누르지 않았습니다.
