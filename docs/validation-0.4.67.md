# v0.4.67 — 계획 모드와 병렬 배정 개선

2026-11-24, Windows x64.

## 변경

- 입력창의 '계획 먼저' 버튼을 채팅별 '계획 모드' 토글로 바꿨습니다(Alt+P, 상태는 채팅에 저장). 켜면 입력창 테두리·안내 문구·'계획 세우기' 버튼으로 구분되고, 토글 저장이 확인될 때까지 전송을 막습니다. 원격 웹도 같은 토글(`POST /api/chats/:id/plan-mode {on}`)을 지원합니다.
- 계획 모드에서 보낸 지시는 읽기 전용 계획 턴이 됩니다. 마스터는 작업자를 쓰지 않고 직접 살핀 뒤 필요한 결정을 `ask_user`로 묻고, 작업별 id·종류·담당 계열·범위·group·완료 기준을 담은 계획을 `propose_plan`으로 제출합니다. 제출한 계획만 승인 대기가 되며, 승인 대기 중 보낸 메시지는 수정 요청으로 새 버전을 만듭니다.
- 승인 버튼은 화면의 계획을 `planId:version`으로 보내고, 그 사이 다른 계획이나 새 버전이 제안됐으면 메인이 '계획이 바뀌었습니다'로 거절합니다. 승인하면 계획 모드가 꺼지고 group 단위로 병렬 실행됩니다. 실행 중 파일 변경은 승인된 작업 범위(+ `extend_plan_scope`로 허용한 범위) 안으로 제한됩니다.
- 계획 패널에 버전, 작업 종류·담당 계열·범위·완료 기준·리뷰 대상, group별 '동시 진행' 묶음, 앞 group 대기 표시, 마스터 질문 답변 대기 배지를 표시합니다. '시작 가능' 판정은 메인 실행 게이트와 같은 규칙을 씁니다.
- 비계획 모드: `route_request`에 작업 분류(`split`: single/parallel/sequential)를 기록하고, parallel이면 첫 배정을 `ask_parallel` 한 번으로 하도록 게이트합니다. 마스터의 `ask_parallel` 기본은 결과를 바로 받는 방식(reportsOnly)입니다. 새 도구 `wait_results`·`amend_scope`를 추가했고, 존재하지 않는 scope 경로는 거절 대신 경고와 접두사 제안을 돌려줍니다.
- 범위 잠금 오탐 수정: 범위가 없는 의견·리뷰 작업자의 명령이 폴더 전체를 잠그지 않고, 명령이 실행되는 동안만 구현 쓰기와 충돌하는 짧은 명령 잠금을 잡습니다(거절되면 즉시 해제).
- 읽기 명령 판정 보강: `cd … &&`, 표준 오류 버림, `grep`, `git grep`/`blame`을 읽기로 인정하고, 외부 명령을 실행하는 `git grep -O`/`--open-files-in-pager`는 차단합니다.
- Claude 설정의 `permissions.deny` 때문에 앱 협업 도구가 세션에서 빠지면, 빠진 도구와 해당 설정 파일을 알리는 경고를 표시합니다.

## 검증

- TypeScript main/renderer 통과.
- 단위 테스트 831개 모두 통과(계획 모드 흐름·병렬 게이트·범위 검증·잠금 오탐·deny 감지·원격 경로, 렌더러의 group 계산·시작 가능 판정·토글 대기·버전 인자 포함).
- electron-vite build 통과.
- 비작성자 교차 리뷰(지피티·클로드)를 여러 차례 수행하고 지적 사항을 반영했습니다.

실제 앱 화면과 실제 CLI 세션에서의 수동 확인, e2e는 수행하지 않았습니다. 영향 경로를 알 수 없는 셸 명령은 승인 범위로 강제하지 못하며 기존 명령 승인 절차가 담당합니다. 범위 포함 판정은 보수적입니다(같은 문자열 또는 `폴더/**`). 명령 잠금의 도구 ID 일치는 실제 CLI로 확인하지 않았고, deny 감지도 실제 deny 상태에서 수동으로 확인하지 않았습니다.
